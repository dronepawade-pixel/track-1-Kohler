How the solution works

Interpret the brief.
Respect the constraints.

Language understanding proposes candidates; deterministic checks decide what is shown. Nothing reaches the layout unless it fits the room, the budget and the catalog.

Step 1 · Understand

Structure the brief.

Room L×W×H, doors & windows, budget in ₹, style — Minimalist, Luxury or Zen — plus free-text needs. Normalized before any model call.

Step 2 · Match

Retrieve candidates.

The model ranks only pre-filtered catalog rows (≤40) against style and functional fit. Output is strict JSON: one item per category.

Step 3 · Verify

Check, then place.

Code confirms each SKU exists, the total stays within budget, footprints fit the room, and nothing overlaps. Failures are removed or reported, never rendered.

What the solution delivers

An answer to the brief,
not just a list of products.

For each set of inputs, the system returns the bundle, its placement, and its cost — with gaps stated plainly.

Output 1 · Bundle

Compatible set.

Faucet, toilet, shower and vanity drawn only from verified catalog rows, with a short note per choice explaining the style and functional fit. Anything unverified is labeled Unknown.

Output 2 · Placement

2D plan + 3D view.

Footprints placed to clearances in the 2D planner; the same layout drives the 3D viewer via GLB models. 2D remains complete where 3D assets are missing.

Output 3 · Reconciliation

Budget + limits.

Line-item totals recomputed against the budget limit, with over-budget or misfitting combinations removed or flagged rather than shown. Saved with versions for revision.
